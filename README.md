# 차곡차곡 숙제 노트

이병준 학생과 엄마가 함께 사용하는 학원 숙제·단어 사진 관리 웹사이트의 소스입니다.

- **운영 중인 사이트:** https://byungjun-homework-notebook.basicstone14.chatgpt.site
- **전체 요구사항 프롬프트:** [PROMPT.md](PROMPT.md)
- **실제 사용방법:** [사용방법.txt](사용방법.txt)

## 주요 기능

- 월~금 학원 시간표, 오늘 요일 강조, 엄마 계정의 시간표 수정
- 숙제 작성·공유 저장과 `해야 할 숙제 → 학생 완료 → 엄마 확인 완료`
- 수·금 영어 단어시험 사진 저장·크게 보기·예습 통과 직접 체크
- 첫 화면의 마감 지남·오늘 마감·내일 마감 표시와 해당 숙제 바로가기
- 로그인 계정별 권한: 엄마만 수정·삭제·엄마 확인, 학생은 등록·학생 체크, 다른 초대 계정은 보기 전용
- 모바일 화면, 약 10초 간격 공유 기록 갱신, 동시 수정 충돌 확인

사진을 자동으로 인식하는 OCR 기능은 사용하지 않습니다. 실제 숙제 기록·사진·로그인 세션·배포용 인증키는 이 저장소에 포함되지 않습니다.

## 개발 경험이 없어도 사용하기

숙제를 등록하거나 확인할 때는 위 운영 사이트에 접속하면 됩니다. ChatGPT 앱 설치 없이 휴대폰 브라우저로 사용할 수 있습니다.

엄마 계정으로 로그인하면 페이지 안에서 시간표와 숙제 내용을 수정할 수 있습니다. 일상적인 기록 변경에는 GitHub나 코딩 도구가 필요하지 않습니다.

## GitHub에서 받거나 수정하기

1. 저장소의 **Code → Download ZIP**으로 전체 소스를 내려받습니다.
2. 브라우저에서 파일을 수정하려면 해당 파일을 열고 연필 모양의 **Edit**를 누릅니다.
3. 변경 내용을 입력하고 **Commit changes**로 GitHub에 저장합니다.
4. 커밋하면 GitHub Actions에서 테스트와 빌드를 실행합니다.

GitHub 커밋은 소스 저장입니다. 현재 운영 사이트에 반영하려면 별도로 Sites 배포 과정을 거쳐야 합니다. 이 저장소에는 자동 배포나 GitHub Pages 게시를 설정하지 않았습니다.

  deadline-ui.js      첫 화면 마감 임박 표시·바로가기
  deadlines.js        마감일 분류 로직

scripts/build.mjs     배포용 Worker 생성

## PC에서 테스트와 빌드

**Node.js 24 이상**을 설치하고 프로젝트 폴더에서 실행합니다. 별도 npm 라이브러리 설치는 필요하지 않습니다.

```sh
node --version
npm test
npm run build
```

빌드 결과는 `dist/server/index.js`에 만들어집니다. `dist/`는 다시 생성할 수 있으므로 Git에 올리지 않습니다.

`app/index.html`에는 빌드 과정에서 합쳐지는 코드가 있습니다. 이 파일을 더블클릭하는 방식으로 공유 저장·로그인 기능을 실행할 수는 없습니다.

## 서버 설정과 배포

현재 앱은 **ChatGPT Sites의 로그인 기능**, **Cloudflare Workers 호환 런타임**, **D1 데이터베이스**, **R2 파일 저장소**를 사용합니다. 정적 페이지용 GitHub Pages만 켜서는 공유 저장과 계정별 권한이 동작하지 않습니다.

### 로그인 이메일 설정

공개 소스에는 실사용 이메일을 넣지 않았습니다. 배포할 서버의 환경변수에 아래 두 값을 설정하세요.

| 이름 | 입력할 값 |
|---|---|
| `MOM_EMAIL` | 수정·삭제·엄마 확인을 허용할 실제 엄마 이메일 |
| `STUDENT_EMAIL` | 등록·학생 완료·예습 체크를 허용할 실제 학생 이메일 |

두 이메일은 서로 달라야 합니다. 값이 없으면 API가 설정 오류를 반환하도록 했습니다. `.env.example`은 작성 예시이며 Worker가 해당 파일을 자동으로 읽지는 않습니다. 실제 값은 호스팅의 런타임 환경변수 설정에 등록하세요.

Sites는 로그인한 방문자의 `oai-authenticated-user-id`와 `oai-authenticated-user-email`을 서버에 전달합니다. 앱은 이 정보로 권한을 판단합니다. 다른 호스팅으로 옮길 때는 검증된 로그인 처리를 연결하고, 사용자가 직접 보낸 이메일·헤더를 인증 증명으로 사용하지 않도록 해야 합니다.

### 저장소 설정

- D1 바인딩: `DB`
- R2 바인딩: `BUCKET`
- SQL 마이그레이션: `drizzle/`의 번호 순서
- Sites 설정: `.openai/hosting.json`

설정 파일의 프로젝트 ID는 현재 운영 사이트를 가리킵니다. 기존 사이트를 이어서 관리할 때는 유지하고, 다른 사이트를 새로 만들 때는 새로 발급된 실제 프로젝트 ID로 바꾸세요.

기존 배포를 GitHub 소스로 교체하려면 먼저 `MOM_EMAIL`과 `STUDENT_EMAIL`을 해당 사이트 런타임에 등록한 뒤 테스트·빌드·Sites 배포를 진행하세요. GitHub에 소스를 올리는 작업 자체는 현재 운영 사이트를 변경하지 않습니다.
